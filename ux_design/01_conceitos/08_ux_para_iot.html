Aula 8 - UX especifico para IoT

IoT tem problemas que apps comuns nao tem: o aparelho pode estar offline, lento ou fisicamente longe. O design precisa lidar com isso.

Desafio IoTBoa pratica de UX
Dispositivo demora a responderMostre "enviando..." e depois confirme o resultado real
Dispositivo offlineDiga "Sem conexao" + ultima leitura + horario dela
Dados desatualizadosMostre "atualizado ha 2 min"; use cor cinza se estiver velho
Acao com risco (bomba, fechadura)Confirmacao antes; botao de parar sempre visivel
Numeros tecnicosTraduza: "Solo seco" em vez de "312"; mostre unidade (°C, %)
Varios dispositivosNome claro ("Sala", "Estufa"), agrupe por comodo
Primeiro uso (pareamento)Passo a passo curto, com barra de progresso
AlertasSo avise o que importa; evite spam de notificacao
Seguranca/privacidadePeca senha, explique quais dados sao coletados

Estados que toda tela IoT deve ter

EstadoExemplo de texto
CarregandoBuscando dados...
NormalEstufa 27,5 °C - OK
VazioNenhum dispositivo. Toque em "Adicionar".
ErroSem conexao com a Estufa. Verifique o Wi-Fi.
Offline com cacheUltima leitura: 26,9 °C (ha 10 min)
Regra de ouro: a tela deve sempre mostrar o estado real do dispositivo, nao so o que o usuario pediu. Se tocou em "Ligar", so mostre "Ligado" depois que o aparelho confirmar.
Exercicios
  1. Escreva os 5 estados (carregando, normal, vazio, erro, offline) para um app de fechadura inteligente.
  2. Qual acao do seu projeto IoT precisa de confirmacao? Por que?
